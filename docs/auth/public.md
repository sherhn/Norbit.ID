# Документация API аутентификации (Public Endpoints)

## Общая информация

Public endpoints предназначены для взаимодействия с клиентской стороной (браузеры, мобильные приложения, фронтенд-приложения). Все эндпоинты доступны по префиксу `/api/auth`.

---

## Авторизация и сессии

### Получение CSRF токена

**Endpoint:** `GET /api/auth/get-csrf-token`

**Требования:**
- Действующая сессия (валидная cookie `norbit.id`)
- Метод: GET или POST

**Описание:**
Генерирует и возвращает CSRF токен для текущей сессии пользователя. CSRF токен необходим для защиты от межсайтовой подделки запросов при выполнении операций, изменяющих состояние (POST, PUT, PATCH, DELETE).

**Response (200 OK):**
```json
{
  "message": "CSRF token generated",
  "csrf_token": "abc123...",
  "csrf_token_header": "X-CSRF-Token",
  "expires_in": 1800
}
```

**Rate limiting:** 30 запросов в минуту, 100 в час

---

### Регистрация нового пользователя

**Endpoint:** `POST /api/auth/registration`

**Требования:**
- JSON в теле запроса
- Поля: `username`, `email`, `password`

**Входные данные:**
- `username`: 3-12 символов, разрешены буквы, цифры, дефисы и подчеркивания
- `email`: валидный email адрес
- `password`: минимум 8 символов, должен содержать цифры, заглавные и строчные буквы

**Описание:**
Создает новый аккаунт пользователя. После успешной регистрации отправляет код подтверждения на email. Аккаунт остается неверифицированным до подтверждения email.

**Response (201 Created):**
```json
{
  "message": "Registration Success",
  "detail": "Verification code sent to email"
}
```

**Rate limiting:** 30 запросов в минуту, 100 в час, 5 в 30 секунд

---

### Вход в систему

**Endpoint:** `POST /api/auth/login`

**Требования:**
- JSON в теле запроса
- Поля: `email`, `password`

**Описание:**
Аутентификация пользователя. Проверяет учетные данные и статус аккаунта. В зависимости от состояния аккаунта может:
- Требовать подтверждения email (если аккаунт не верифицирован)
- Требовать 2FA (если включена двухфакторная аутентификация)
- Создавать сессию (если все проверки пройдены)

**Response (успешный вход):**
```json
{
  "message": "Login successful",
  "account": {...},
  "session": {...},
  "tokens": {...},
  "csrf": {...}
}
```
**При успехе устанавливает cookie `norbit.id`.**

**Rate limiting:** 30 запросов в минуту, 100 в час, 5 в 30 секунд

---

### Подтверждение операций

**Endpoint:** `POST /api/auth/verify`

**Требования:**
- JSON в теле запроса
- Обязательные поля: `operation`, `code`
- Дополнительные поля зависят от операции

**Поддерживаемые операции:**
1. **registration** - подтверждение регистрации
   - Дополнительно: `email`
   - После подтверждения создает сессию

2. **login** - подтверждение 2FA
   - Дополнительно: `email`
   - Если 2FA не включена - включает ее
   - Если 2FA включена - проверяет код и создает сессию

3. **reset** - сброс пароля
   - Дополнительно: `new_password`
   - Требует валидной сессии
   - После сброса удаляет все сессии пользователя

4. **delete** - удаление аккаунта
   - Требует валидной сессии
   - После подтверждения полностью удаляет аккаунт из БД

**Описание:**
Универсальный эндпоинт для подтверждения различных операций с помощью кодов, отправленных на email.

**Rate limiting:** 5 запросов в 2 минуты, 20 в час, 3 в минуту

---

### Запрос кода 2FA

**Endpoint:** `POST /api/auth/2fa`

**Требования:**
- JSON в теле запроса
- Поле: `email`

**Описание:**
Отправляет код двухфакторной аутентификации на email пользователя. Используется для повторной отправки кода или при включении 2FA.

**Response (200 OK):**
```json
{
  "message": "If an account exists with this email, a verification code has been sent"
}
```

**Rate limiting:** 5 запросов в минуту, 10 в час

## Управление сессиями

### Выход из текущей сессии

**Endpoint:** `POST /api/auth/logout`

**Требования:**
- Действующая сессия (валидная cookie)
- CSRF токен в заголовке `X-CSRF-Token`
- Метод: POST

**Описание:**
Завершает текущую сессию пользователя. Удаляет сессию из базы данных, CSRF токен из Redis и очищает сессионную cookie.

**Response (200 OK):**
```json
{
  "message": "Logged out successfully",
  "detail": "Session terminated and cookie cleared",
  "session_deleted": true
}
```

**Rate limiting:** 20 запросов в минуту, 50 в час

---

### Выход из всех сессий

**Endpoint:** `POST /api/auth/logout-all`

**Требования:**
- Действующая сессия (валидная cookie)
- CSRF токен в заголовке `X-CSRF-Token`
- Метод: POST

**Описание:**
Завершает все активные сессии пользователя. Полезно при подозрении на несанкционированный доступ или при смене пароля.

**Response (200 OK):**
```json
{
  "message": "Logged out from all devices",
  "detail": "All sessions terminated and cookie cleared",
  "account_id": 123,
  "all_sessions_deleted": true
}
```

**Rate limiting:** 5 запросов в минуту, 10 в час

---

## Управление аккаунтом

### Запрос на сброс пароля

**Endpoint:** `POST /api/auth/reset`

**Требования:**
- JSON в теле запроса
- Поле: `email`

**Описание:**
Отправляет код подтверждения для сброса пароля. Требует, чтобы аккаунт был верифицирован.

**Response (200 OK):**
```json
{
  "message": "If an account exists with this email, a verification code has been sent"
}
```

**Rate limiting:** 5 запросов в минуту, 10 в час

---

### Запрос на удаление аккаунта

**Endpoint:** `POST /api/auth/delete`

**Требования:**
- Действующая сессия (валидная cookie)
- CSRF токен в заголовке `X-CSRF-Token`
- Метод: POST

**Описание:**
Инициирует процесс удаления аккаунта. Отправляет код подтверждения на email пользователя. После подтверждения через `/verify` аккаунт будет полностью удален.

**Response (200 OK):**
```json
{
  "message": "Verification code sent to email",
  "detail": "Please check your email for the verification code..."
}
```

**Rate limiting:** 5 запросов в минуту, 10 в час

---

### Обновление access токена

**Endpoint:** `POST /api/auth/refresh`

**Требования:**
- JSON в теле запроса
- Поле: `refresh_token`
- CSRF токен в заголовке `X-CSRF-Token` (опционально, если есть сессия)

**Описание:**
Обновляет истекший access токен с помощью валидного refresh токена. Проверяет соответствие refresh токена сессии в БД.

**Response (200 OK):**
```json
{
  "message": "Token refreshed",
  "access_token": "new_token_here",
  "expires_in": 900
}
```

**Rate limiting:** 10 запросов в минуту, 30 в час

## Утилиты

### Проверка здоровья сервиса

**Endpoint:** `GET /api/auth/health`

**Описание:**
Простой эндпоинт для проверки работоспособности сервиса. Возвращает "OK" при успешном выполнении.

**Response (200 OK):** `"OK"`

**Rate limiting:** 30 запросов в минуту, 180 в час

## Формат сессионной cookie

Имя cookie: `norbit.id`
Формат: `session_id:access_token`

**Параметры cookie:**
- `HttpOnly`: true (защита от XSS)
- `Secure`: true в продакшене (только HTTPS)
- `SameSite`: Lax (баланс безопасности и кросс-доменных запросов)
- `Domain`: настраивается через переменную окружения
- `Path`: `/`
- `Max-Age`: совпадает со временем жизни refresh токена (30 дней)

### Обязательные заголовки для CSRF-защищенных операций:

```
X-CSRF-Token: полученный_токен_из_/get-csrf-token
```

### Формат запросов:

Все запросы, требующие данных, должны отправляться с заголовком:
```
Content-Type: application/json
```

## Обработка ошибок

**Общие коды ответов:**

- `200 OK` - успешное выполнение
- `400 Bad Request` - невалидные входные данные
- `401 Unauthorized` - требуется аутентификация/невалидная сессия
- `403 Forbidden` - недостаточно прав/невалидный CSRF токен
- `404 Not Found` - ресурс не найден
- `409 Conflict` - конфликт (например, email уже существует)
- `423 Locked` - аккаунт временно заблокирован
- `429 Too Many Requests` - превышен лимит запросов
- `500 Internal Server Error` - внутренняя ошибка сервера

**Формат ошибок:**
```json
{
  "message": "Описание ошибки",
  "detail": "Детальное описание (опционально)"
}
```
