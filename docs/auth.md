# Микросервис аутентификации (Яндекс.ID-подобный)

## 📋 Общее описание

Микросервис аутентификации представляет собой централизованную систему управления пользовательскими аккаунтами, сессиями и авторизацией для экосистемы сервисов. Аналогично Яндекс.ID, система предоставляет единый аккаунт для доступа к различным сервисам компании.

**Основные возможности:**
- Регистрация и аутентификация пользователей
- Управление сессиями и токенами
- Двухфакторная аутентификация (2FA)
- CSRF-защита
- Внутреннее API для микросервисов
- Интеграция с другими сервисами компании

- **Backend:** Python 3.14, Flask
- **База данных:** PostgreSQL (основное хранение)

- **Аутентификация:** JWT, bcrypt
- **Контейнеризация:** Docker, Docker Compose
- **API:** RESTful JSON

## 🔐 Безопасность

### Уровни безопасности

#### 1. Защита пользовательских данных
- **Хеширование паролей:** bcrypt с автоматической солью
- **Хеширование токенов:** SHA256 для всех токенов в БД
- **HTTPS:** Обязательное использование TLS в продакшене
- **Cookie защита:** HttpOnly, Secure, SameSite=Lax

#### 2. Защита сессий
- **Сессионные куки:** Формат `session_id:access_token`
- **JWT токены:** Подписанные токены с ограниченным сроком жизни
- **Проверка сессий:** Валидация в базе данных при каждом запросе
- **Автоматический логаут:** При неактивности и по истечении срока

#### 3. CSRF защита
- **Генерация токенов:** Уникальные токены для каждой сессии
- **Хранение:** Redis с TTL 30 минут
- **Проверка:** Обязательная для всех state-changing операций

#### 4. Rate limiting
- **Многоуровневый лимит:** Разные лимиты для разных операций
- **Базовая защита:** 5-30 запросов в минуту
- **Чувствительные операции:** Строгие лимиты (регистрация, логин)

#### 5. Внутренняя безопасность
- **Двухуровневая аутентификация:** API Key → Service Token
- **Изоляция данных:** Сервисы получают только необходимую информацию
- **Аудит:** Логирование всех операций с сессиями и токенами

### Меры против атак

| Угроза | Меры защиты |
|--------|-------------|
| **Brute force** | Rate limiting, блокировка аккаунтов после N попыток |
| **XSS** | HttpOnly куки, экранирование данных |
| **CSRF** | CSRF токены, проверка Origin/Referer |
| **Session hijacking** | Хеширование сессий в БД, регулярная ротация |
| **Credential stuffing** | Проверка утекших паролей (опционально) |
| **DDoS** | Rate limiting, Cloudflare/WAF |

## 📡 API Эндпоинты

### Публичное API (`/api/auth/*`)
Для клиентских приложений, браузеров и мобильных устройств.

**Основные категории:**
1. **Авторизация:** Регистрация, логин, верификация
2. **Управление сессиями:** Логаут, обновление токенов
3. **Управление аккаунтом:** Сброс пароля, удаление аккаунта
4. **Утилиты:** Проверка здоровья, CSRF токены

### Внутреннее API (`/internal/auth/*`)
Для взаимодействия между микросервисами компании.

**Основные категории:**
1. **Авторизация сервисов:** Получение сервисных токенов
2. **Валидация сессий:** Проверка пользовательских сессий
3. **Управление сессиями:** Принудительный логаут
4. **Информация:** Получение данных о пользователях и сессиях

## 💾 Хранение данных

### PostgreSQL (основная БД)
**Таблицы:**
- `accounts` - Пользовательские аккаунты
- `user_sessions` - Активные сессии пользователей
- `service_tokens` - Токены внутренних сервисов

### Redis (временное хранилище)
**Экземпляры:**
1. **REDIS_CODES_URL:** Коды подтверждения (регистрация, сброс пароля, 2FA)
2. **REDIS_CSRF_URL:** CSRF токены для защиты от межсайтовых атак
