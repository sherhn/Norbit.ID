# Переменные окружения (`.env`) - Документация

## Общая информация
Файл `.env` содержит конфигурационные переменные окружения для системы аутентификации и связанных сервисов. Все переменные разбиты на логические секции.

---

## Настройки Flask
### `JWT_SECRET_KEY`
- **Описание:** Секретный ключ для подписи JWT токенов. Должен быть случайной строкой достаточной длины.
- **Формат:** Строка (64+ символов)
- **Пример:** `pQi7cMiBNm8Tbj2zNYUPFrmyok5b5B7c`
- **Важно:** Никогда не коммитить в репозиторий, хранить в секретах!

### `JWT_ACCESS_TOKEN_EXPIRES`
- **Описание:** Время жизни Access токена в секундах.
- **Значение по умолчанию:** 900 (15 минут)
- **Рекомендации:** Для повышения безопасности используйте короткое время жизни.

### `JWT_REFRESH_TOKEN_EXPIRES`
- **Описание:** Время жизни Refresh токена в секундах.
- **Значение по умолчанию:** 2592000 (30 дней)
- **Примечание:** Refresh токены имеют более длительный срок жизни для поддержания сессий.

---

## Сервисные токены
### `SERVICE_TOKEN_EXPIRES_HOURS`
- **Описание:** Время жизни сервисного токена в часах.
- **Значение по умолчанию:** 1
- **Назначение:** Токены для внутренних сервисов, позволяющие взаимодействовать с API аутентификации.

---

## Настройки сессий
### `MAX_SESSIONS_PER_USER`
- **Описание:** Максимальное количество одновременных активных сессий для одного пользователя.
- **Значение по умолчанию:** 10
- **Примечание:** При превышении лимита удаляются самые старые сессии.

### `SESSION_COOKIE_NAME`
- **Описание:** Имя сессионной куки, которая будет устанавливаться в браузере.
- **Значение по умолчанию:** `session_token`
- **Альтернативы:** `norbit.id` (используется в некоторых частях системы)

### `SESSION_COOKIE_HTTPONLY`
- **Описание:** Запрещает доступ к куки через JavaScript (защита от XSS).
- **Значения:** `True`/`False`
- **Рекомендуется:** `True` для безопасности

### `SESSION_COOKIE_SECURE`
- **Описание:** Куки передаются только по HTTPS.
- **Значения:** `True`/`False`
- **Примечание:** В продакшене всегда должно быть `True`.

### `SESSION_COOKIE_SAMESITE`
- **Описание:** Политика SameSite для куки, защита от CSRF.
- **Значения:** `Strict`/`Lax`/`None`
- **Рекомендуется:** `Lax` (баланс между безопасностью и удобством)

### `SESSION_COOKIE_DOMAIN`
- **Описание:** Домен, для которого будет установлена кука.
- **Значение:** Строка или `None`
- **Примечание:** Если `None`, кука устанавливается для текущего домена.

## Внутренняя аутентификация
### `INTERNAL_API_KEY`
- **Описание:** API ключ для внутреннего взаимодействия между сервисами.
- **Назначение:** Используется для получения сервисных токенов.
- **Безопасность:** Должен быть уникальным и храниться в секретах.

### `SECRET_KEY`
- **Описание:** Секретный ключ Flask приложения.
- **Назначение:** Используется для подписи сессий и других криптографических операций.
- **Важно:** Отличается от `JWT_SECRET_KEY`!

---

## База данных PostgreSQL
### `POSTGRES_USER`
- **Описание:** Имя пользователя для подключения к PostgreSQL.
- **Пример:** `norbit`

### `POSTGRES_PASSWORD`
- **Описание:** Пароль для подключения к PostgreSQL.
- **Требования:** Сложный пароль, хранить в секретах.

### `AUTH_POSTGRES_DB`
- **Описание:** Название базы данных для сервиса аутентификации.
- **Пример:** `auth_db`

### `AUTH_DATABASE_URL`
- **Описание:** Полный URL для подключения к базе данных аутентификации.
- **Формат:** `postgresql://user:password@host:port/database`
- **Примечание:** Обычно собирается из других переменных.

---

## Redis конфигурация
### `AUTH_LIMIT_REDIS`
- **Описание:** Redis для хранения данных rate limiting.
- **URL формат:** `redis://host:port/db_number`
- **Пример:** `redis://redis:6379/0`

### `REDIS_CODES_URL`
- **Описание:** Redis для хранения кодов подтверждения (верификации, 2FA и т.д.).
- **База данных:** 1
- **Пример:** `redis://redis:6379/1`

### `REDIS_CSRF_URL`
- **Описание:** Redis для хранения CSRF токенов.
- **База данных:** 2
- **Пример:** `redis://redis:6379/2`

---

## Настройки CSRF
### `CSRF_TOKEN_EXPIRES`
- **Описание:** Время жизни CSRF токена в секундах.
- **Значение по умолчанию:** 1800 (30 минут)
- **Примечание:** Токен обновляется при каждом использовании, если включена соответствующая опция.

### `CSRF_TOKEN_LENGTH`
- **Описание:** Длина CSRF токена в символах.
- **Значение по умолчанию:** 32

### `CSRF_REFRESH_ON_USE`
- **Описание:** Обновлять ли время жизни CSRF токена при каждом использовании.
- **Значения:** `'True'`/`'False'` (строковые!)
- **Примечание:** Может быть полезно для длительных сессий.

---

## Сервис уведомлений
### `INTERNAL_NOTIFICATION_SERVICE_URL`
- **Описание:** URL внутреннего сервиса уведомлений.
- **Пример:** `http://notifications_service:5001`

### `NOTIFICATION_QUEUE_REDIS_URL`
- **Описание:** Redis для очереди отправки уведомлений.
- **База данных:** 3
- **Пример:** `redis://redis:6379/3`

### `SMTP_SERVER`, `SMTP_PORT`, `SMTP_LOGIN`, `SMTP_PASSWORD`
- **Описание:** Настройки SMTP сервера для отправки email.
- **Примечание:** Помечены как HIDDEN - должны быть установлены в реальном окружении.

### `SENDER_EMAIL`
- **Описание:** Email отправителя для всех уведомлений.
- **Требования:** Должен быть действительный email, разрешенный для отправки.

### `SENDER_NAME`
- **Описание:** Имя отправителя, отображаемое в письмах.
- **Пример:** `Jeb`

### `RQ_QUEUE_NAME`
- **Описание:** Название очереди задач для фоновой обработки.
- **Пример:** `email_queue`

### `RQ_RETRY_MAX`
- **Описание:** Максимальное количество повторных попыток при ошибке отправки.
- **Значение по умолчанию:** 3

### `RQ_RETRY_INTERVAL`
- **Описание:** Интервал между повторными попытками в секундах.
- **Значение по умолчанию:** 60
